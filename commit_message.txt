feat: add queue metrics and worker on_active/on_error callbacks

Restore the metrics collection path that had been stripped from the
moveToFinished-14.lua port. The script now accepts ARGV[11]
(maxMetricsSize, empty string disables collection, matching upstream
bullmq@5.8 semantics) and calls the upstream collectMetrics include to
record per-minute job counts under metrics:<state> / metrics:<state>:data.

- Add lua/includes/batches.lua and lua/includes/collectMetrics.lua
  (verbatim upstream, flattened for the one-level include resolver) and
  lua/getMetrics-2.lua, all registered in the script loader.
- Add WorkerOptions.metrics (MetricsOptions { max_data_points }) and
  WorkerBuilder::metrics(...), plumbed into both moveToFinished call
  sites so completed and failed jobs are counted.
- Add Queue::get_metrics(state, start, end) -> Metrics mirroring Node's
  Queue.getMetrics (meta count/prevTS/prevCount + LRANGE data points).
- Add WorkerBuilder::on_active(|job|) invoked when a job starts
  processing, and on_error(|err|) invoked on internal fetch-loop errors
  (moveToActive failures and non-timeout BZPOPMIN errors), following the
  existing Arc<dyn Fn> callback pattern.

Integration tests cover metrics enabled (count + key presence), metrics
disabled (no metrics keys created, preserving wire-compat with upstream
when maxMetricsSize is empty), failed-state metrics, and on_active
firing once per job.
